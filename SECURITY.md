# Security

## Reporting a vulnerability

Please do not open a public issue for a security problem.

Use **private vulnerability reporting** on the repository concerned — *Security → Report a vulnerability* — which is
enabled on every repository of this organization. If that is not possible, write to **security@nexiflow.ai**.

Tell us what you found, where (repository · tag or `PROVENANCE.json` digest · file), how to reproduce it, and what you
think the impact is. A proof of concept helps; exploitation of anything that is not yours does not.

## What to expect

- an acknowledgement within **5 working days**;
- a first assessment within **15 working days**;
- a fix, a mitigation or a reasoned decision not to act within **90 days** of the report — the disclosure window.
  After 90 days you are free to publish; we will ask for more time only with a reason and a date.

We credit reporters in the advisory unless they prefer not to be named. We do not run a bug bounty.

## Scope

What is published under NexiFlow: the documentation site and its source, the design system and the component
workshop, the packs and the toolkit, the decision dataset and the recipe, the landing page. The product itself
(the running suite) is not public; a report about it is still welcome at the address above.

A content mistake that is not a security problem is an issue, not a report.
